# DiploChain (PD3 MVP)

Prototype developed for the Blockchain and Cryptocurrencies course (UFSC). It implements single and batch issuance of *W3C Verifiable Credentials* (VCs), Merkle root anchoring on an EVM network, EIP-712 meta-transactions via a relayer, on-chain revocation, and independent verification.

- Step-by-step usage guide [USER_GUIDE.md](./USER_GUIDE.md)
- Technical adjustments to the *Technical White Paper* (PD2) [WHITEPAPER_ADJUSTMENTS.md](./WHITEPAPER_ADJUSTMENTS.md)
- Scope boundary between the course MVP and the target product [MVP_SCOPE.md](./MVP_SCOPE.md)

## Repository structure

- `contracts/` contains the `DiploChain.sol` contract, automated tests (scenarios S1 to S4 and N1 to N7), the batch gas benchmark, and deployment scripts.
- `core/` contains the shared TypeScript library (JCS canonicalization, `salt` generation, `leafHash` calculation, Merkle tree, EIP-712 signatures, and verification engine), the independent CLI (S3), and the `did:web` comparison script.
- `web/` contains the Vite, React, and TypeScript graphical interface connected directly to the blockchain RPC, with local accounts configured for immediate execution.

## Files used by the application

- **Credential (`.json`)** is the file generated by DiploChain when an issuer creates a credential on the **Issue** tab and clicks **JSON** (for example, `vc-maria-silva.json`). It stores the holder data, issuer signature, and Merkle proof, and is later used on the **Verify** tab or in the CLI.
- **Batch list (`.csv`, optional)** is a plain-text file with one holder per line imported on the **Issue** tab (**Batch** mode). It accepts either names only (using the default course and workload entered in the form) or three columns separated by commas or semicolons (`name,course,workload_hours`), automatically skipping a header line.

## Prerequisites

Node.js (tested on v24), npm, and Git.

## Local execution

### 1. Install dependencies

```bash
cd contracts && npm install && cd ../core && npm install && cd ../web && npm install
```

### 2. Run automated tests, gas benchmark, and `did:web` baseline

```bash
cd contracts && npm test && npm run benchmark && cd ../core && npm run baseline
```

### 3. Start the local blockchain and web interface

In the first terminal, start the local Hardhat node.

```bash
cd contracts && npm run node
```

In the second terminal, deploy the contract (which also registers the default issuer `did:web:extensao.ufsc.br`) and start the web interface at `http://localhost:5173`.

```bash
cd contracts && npm run deploy:local && cd ../web && npm run dev
```

### 4. Issue and verify from the terminal (scenario S3)

In the web interface, open the **Issue** tab, generate a credential, and click **JSON** to download the file (for example, `vc-maria-silva.json`). Then verify that file from the terminal without relying on the web portal.

```bash
cd core && npm run verify -- <path-to-file.json>
```

## Demonstration script

1. On the **Issue** tab, fill in a holder's details and issue a single credential (S1). Check the gas recorded by the relayer, open the **QR Code** modal, and follow the verification link to see the `VALID` verdict across all four dimensions.
2. On the same tab, switch to **Batch**, paste a list of holders or import a `.csv` file, and click **Anchor batch** to anchor all credentials in a single transaction (S2). For larger batch metrics (1, 100, and 1,000 credentials), run `npm run benchmark` inside `contracts/`.
3. Download the `.json` file of an issued credential by clicking **JSON** and run the CLI verifier in the terminal (S3).
4. On the **Verify** tab, open **Paste JSON manually** with a loaded credential and edit the JSON to demonstrate negative cases. Changing the workload produces `TAMPERED` (N1), changing the `issuer` field produces `ISSUER NOT REGISTERED` (N2), and altering `merkleRoot` demonstrates an anchoring failure (N6).
5. On the **Issue** tab, issue a credential with a past expiration date to validate **N7** (`EXPIRED`). Then click **Revoke** on a valid credential to validate **S4** and **N3** (`REVOKED`).
6. On the **Governance** tab, test **Suspend** (`ISSUER SUSPENDED`, N4), reactivate the issuer, enter a timestamp between two issuances in **Compromise date/time**, click **Report compromise** (N5, keeping the first credential `VALID` and marking the second as `UNDER REVIEW`), and click **Close** to confirm `VALID - ISSUER CLOSED`.
7. Run `npm run baseline` inside `core/` to display the comparison between `did:web` and DiploChain on offline S3 and N5 scenarios.

## Optional deployment to Base Sepolia testnet

1. Create a test wallet without real funds and request test ETH from a Base Sepolia faucet.
2. Copy `contracts/.env.example` to `contracts/.env` and set `DEPLOYER_PRIVATE_KEY`.
3. Run the deployment script.

```bash
cd contracts && npm run deploy:sepolia
```

4. In the web interface, open **Configure network** at the top, enter `https://sepolia.base.org` as the RPC URL, and paste the contract address saved in `contracts/deployments/baseSepolia.json`.
